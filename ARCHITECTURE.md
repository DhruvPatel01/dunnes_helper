# System Architecture

## Overview

Single-page application (SPA) built with **Vue 3**, packaged as a **Progressive Web App (PWA)**. Fully client-side — no backend, no API calls. All data lives in the browser.

---

## Tech Stack

| Layer | Technology |
|-------|------------|
| UI Framework | Vue 3 (Composition API) |
| State Management | Pinia (setup-syntax stores) |
| Persistence | IndexedDB (via `idb`), localStorage |
| Styling | Tailwind CSS 3 + PostCSS |
| Build | Vite 5 |
| Package Manager | Bun |
| PWA | vite-plugin-pwa (Workbox) |

## Routing

No router library. `App.vue` reads `window.location.hash` on mount and listens for `hashchange` events, rendering the matching view component. Navigation is driven by `BottomNav.vue` (3-tab bar at the bottom of the screen).

| Hash | View |
|------|------|
| `#lists` | ListView |
| `#catalog` | CatalogView |
| `#history` | HistoryView |

---

## State Management

Three Pinia stores, all using the Composition API setup syntax.

| Store | Backing Storage | Responsibility |
|-------|-----------------|----------------|
| `sessionStore` | localStorage | Current active view (tab navigation) |
| `catalogStore` | IndexedDB (`catalog`) | Full product list; search, sort, CRUD, purchase frequency |
| `listsStore` | IndexedDB (`lists`) | Shopping lists with items, targets, and vouchers |

**List lifecycle:**

```
listsStore (active list with items)
    │
    │  "Complete"
    ▼
historyDb (permanent record)   ← list is deleted from listsStore
```

---

## Persistence

Two storage layers:

```
localStorage
  └── sessionStore (currentView)
  └── last-unavailable item IDs (cross-session tracking in catalogStore)

IndexedDB (schema v3)
  ├── catalog  — products {name, price, purchaseCount, lastPurchasedAt}
  ├── history  — completed sessions {date, items[], totalSpent, target}
  └── lists    — shopping lists {name, target, discount, items[]}
```

IndexedDB is accessed exclusively through the `db/` abstraction layer (`catalogDb.js`, `listsDb.js`, `historyDb.js`).

---

## PWA / Offline

- Service worker generated by `vite-plugin-pwa` (Workbox, `autoUpdate` strategy)
- Pre-caches all static assets (JS, CSS, HTML, icons, fonts) at build time
- No runtime network caching — the app never makes network requests
- Manifest: standalone display, Dunnes green theme (`#00703c`), maskable icon
- `index.html` includes mobile PWA meta tags (`apple-mobile-web-app-capable`, `theme-color`, safe-area insets)

## Component Organization

Components are grouped by feature domain under `src/components/`:

```
components/
├── lists/     — list cards, item rows, search bar, gap bar, move popup
├── catalog/   — product list, CSV import modal, export panel
├── history/   — session list, date editor, add-session modal
└── shared/    — BottomNav, ConfirmDialog
```

Views (`src/views/`) are thin orchestration shells that compose domain components.

---

## Data Flow Summary

1. **Catalog** is populated via CSV import or manual entry → stored in IDB `catalog`
2. **ListView** renders all lists; each list has a `target` (budget) and `discount` (voucher)
3. Items are added via `ListSearchBar`, which searches `catalogStore` and sorts by `purchaseCount`
4. When a list has a target, the search bar suggests frequent items that fit within the remaining budget (gap + €2)
5. **Complete** on a list writes a session record to `historyDb` and deletes the list
6. **HistoryView** reads from `historyDb`; sessions are editable (date) and deletable
